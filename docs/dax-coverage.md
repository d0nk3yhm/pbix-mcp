# DAX Surface Coverage

The authoritative function inventory is taken from the **live Power BI Desktop
engine itself** — `SELECT [FUNCTION_NAME],[ORIGIN] FROM
$SYSTEM.MDSCHEMA_FUNCTIONS` against the workspace `msmdsrv`, keeping ORIGIN 3
and 4 (the DAX surface; ORIGIN 1 is MDX). That is the exact list for the exact
build the corpus is verified against, immune to documentation lag.

| | count |
|---|---|
| DAX functions in the engine (March 2026 build) | **467** |
| implemented and verified | **245** ([supported-dax.md](supported-dax.md)) |
| not yet implemented | **221** |
| empirically not authorable (Desktop refuses in a query) | **2** (`CEILING.MATH`, `FLOOR.MATH`) |

Corpus parity (v0.9.63) means every comparable cell of the 25-file test corpus
matches Desktop. Full-surface parity — every function below, each verified
against the live engine by a per-function conformance harness — is the roadmap.
An unimplemented function returns `None` with status `"unsupported"`; it is
never guessed.

Note the raw list includes entries that are engine-internal or visual-calc-only
(`SAMPLEAXISWITHLOCALMINMAX`, `COLLAPSE`/`EXPAND`, `EXTERNALMEASURE`, the
`INFO.*` metadata family). Part of the roadmap is classifying which of the 285
are user-authorable in a .pbix measure at all — the conformance harness settles
that empirically: a function Desktop itself refuses in a measure is out of
scope, and the doc will record it as such rather than counting it against
parity.
